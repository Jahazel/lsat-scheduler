Follow-up decisions depend on those answers: existing-account migration and safe linking; password verification/recovery if retained; admin MFA enforcement; ordinary versus account-wide logout; session lifetimes and recent authentication; upload formats/size/dimensions; normal extraction allowance, retry/concurrency policy, and budget cutoff behavior; student-confirmed versus server-attested snapshot provenance; privacy/deletion handling; database network restrictions; logging and dependency response policy. Proposed deferrals must name the specific remaining risk and receive the user's decision.

Existing accounts need a migration that does not silently verify an address or transfer an admin role. These details are recommendations pending the next account-security discussion.

## Extraction cost discussion

The current [extractor](../../src/lib/claudeExtract.ts) calls `claude-haiku-4-5-20251001` once through the Messages API, supplies one screenshot plus instructions and a tool schema, and caps output at 1,024 tokens. It does not return or persist usage metrics. The [installed SDK](../../node_modules/@anthropic-ai/sdk/src/client.ts) defaults to two retries and a ten-minute timeout; the app does not override either. One user upload therefore need not mean exactly one provider attempt. A timeout or failed local result is not proof that no provider work was charged.

Current standard [Haiku pricing](https://platform.claude.com/docs/en/about-claude/pricing), checked October 1, 2026, is $1 per million input tokens and $5 per million output tokens. Input includes the image, text, tool schema, and tool-use overhead. [Vision documentation](https://platform.claude.com/docs/en/build-with-claude/vision) lists 1,296 image tokens for a 1,000 by 1,000 image on this model's standard resolution tier. That is an image-only cost of $0.001296; it does not include instructions or output. The forced-tool overhead is currently listed as 588 input tokens, in addition to the submitted schema and text.

For planning only, assume 2,500 total input tokens and 800 output tokens per successful attempt. The calculation is `(2500 × $1 + 800 × $5) / 1,000,000 = $0.0065`, or 0.65 US cents. This is an illustrative workload, not measured DrillMap usage, a guaranteed maximum, or an accuracy result.

At that assumed cost, $10 buys 1,538 whole provider attempts, or eight attempts each for 192 students. Reserving 50% extra attempts for retries/failed-but-billable work reduces the illustrative eight-attempt capacity to 128 students. This allowance is a planning scenario, not a measured retry rate or a safety guarantee. Attempts with different token usage can change both costs and capacity.

These scenarios exclude retries, failed-but-billable attempts, unusual input/output sizes, hosting, database, email delivery, tax, and unrelated organization usage. Eight attempts per month is a scenario, not an agreed student quota. It allows more than roughly one screenshot per week without claiming how many screenshots the actual student workflow needs.

The user expects fewer than 50 active students during the first few months. At the illustrative eight-attempt workload, the 50-student scenario is $2.60 per month before the exclusions above, or $3.90 with 50% extra attempts. The accepted $10 monthly pilot ceiling provides estimated headroom at that scale. It is not a measured forecast or a currently enforced protection. Exact budget enforcement still needs specification. This ceiling concerns extraction charges only, not total application operating cost.

The current provider choice is reasonable to retain while evaluating quality and cost. Lower-cost OCR or image models may save money but require integration and comparison on representative 7Sage screenshots. A local OCR path could keep screenshot bytes on the device; it still needs reliable row parsing and performance checks. No alternative is proven more accurate by its price or general capability description.

The spending requirement should combine application request limits, a conservative reservation for each provider attempt including retries, a global stop, and a provider-side limit or constrained credit balance. A notification alone is not a hard stop. Account quotas alone do not stop abuse through many newly created accounts. A shared $500 organization ceiling is not an agreed DrillMap budget.

Before selecting exact numbers, decide expected launch usage and what happens when extraction stops. Existing schedules and history can remain available, but a student without an approved snapshot cannot currently create a new schedule. The current UI supports correcting extracted rows; a complete manual-entry path without any successful extraction would need a product and provenance decision rather than being assumed to exist.

The [alternative comparison](issue-72-extraction-alternatives.md) records current official pricing, privacy, and maintenance tradeoffs. No candidate has been tested against the same representative screenshots. Retaining Haiku is the current recommendation. The user accepted a $10 monthly extraction pilot ceiling and manual entry if scanning is unavailable. Enforcement still needs application limits and a provider-side safeguard. A hosted extraction path still needs all the agreed security protections even if its published price is lower.
