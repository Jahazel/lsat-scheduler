# Onboarding and Study settings

A student enters their study profile during onboarding. They can later change Study settings. Changes apply to the next weekly schedule created.

## Sub-features

- `onboard` saves the first study profile.
- `capacity` edits every day's minutes or applies one value to all days.
- `preferences` saves the goal score, Test time, goal test month, and preferred practice-test day. Study settings shows the current score as text; only the weekly upload changes it.
- `save-bar` shows the save bar after an edit, hides it when every edit is undone, and reads `Saving…`, then `Saved.` for 6 s, without leaving the page.
- `field-errors` refuses a goal not above the current score and a day outside 30 min to 8 h, and moves focus to the first invalid field.
- `settings-persist` reopens saved values while preserving an existing weekly schedule.

## How to get to it (user POV)

- A first Google sign-in from Signup opens `/onboarding`. A signed-in Account without a Student also reaches it from This week or Study settings.
- Click `Study settings` in desktop navigation or `Settings` at narrow widths to reach `/settings`. This week has no capacity notice or settings link.
- Direct `/settings` links enforce sign-in and onboarding.

## Gotchas

- Study settings does not show or edit Official LSAT attempts yet, and a save keeps the stored ones. Only onboarding records them.
- `Apply` copies the separate All days control to all seven days. Changing All days without Apply changes no daily capacity.
- Every day requires 30 to 480 minutes in 15-minute steps. Selecting zero hours clamps the minutes to a valid value.
- Goal test date options are the LSAT test months after the student-side date, so an Admin's Simulated date shortens the list. A saved month that is no longer offered shows `Select a test date`, and Save then shows `Choose an upcoming LSAT test month.` Inspect the options before choosing.
- The save bar keeps both messages in the DOM and fades one out with `aria-hidden`, so a plain text wait matches the hidden one. Wait on `[role="status"] > :not([aria-hidden])` with the message text.
- In Study settings, field messages show only after Save is pressed, then follow each edit until the save succeeds.
- A row message appears when focus leaves its box. After a mouse press, it waits for the press to end, so the pressed button does not move under the pointer.
- `SCREENSHOT_EXTRACTOR=fake` ignores the image, so any valid PNG proves the upload path. Launch with `VERIFY_SCREENSHOT_EXTRACTOR=fake-wrong-page` to read every RC screenshot as a wrong page, or `fake-no-percentages` to read it as a passage-type page with no percentages, in onboarding and the weekly upload without a stub. LR reads stay as in `fake`. Reading a real 7Sage screenshot needs the real extractor and an Anthropic key, which this helper turns off.
